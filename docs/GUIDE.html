Get started

0 Read this first

Three ideas make everything else easy.

You type commands in two different places

Each command box on this page has a label so you always know where to type it.

LabelWhereLooks like
TerminalA normal terminal window (PowerShell, Windows Terminal, macOS Terminal). Not inside Claude.cc doctor
In chatThe message box of a running Claude Code session./cc status

Inside a chat, put /cc (or !cc) in front. The command runs on your machine and does not use any of your Claude usage.

Heads-up: "A hook blocked your prompt" is normal When you run /cc something in a chat, Claude Code shows a label saying a hook blocked your prompt. That is just how it shows results that never went to the model. The first line of the result says whether it worked, for example [cc palace init: done - ran locally, no tokens used]. If it says FAILED, read the lines under it.
Windows: cc can also mean a C compiler If you have MSYS2, MinGW or Git Bash, typing cc there may start the C compiler instead and print errors like collect2.exe: error or a list of compiler options. Use PowerShell or Command Prompt for cc. If you must use another shell, run cc.cmd instead.

Some things always need you at a terminal

Logging in, downloading models, installing the local runtime and starting servers cannot be done from inside a chat. This is deliberate: nothing is downloaded or logged in behind your back. The commands that cannot run in a chat will tell you so and show the terminal command to use.

Get started

1 Install

Always do a dry run first. It lists exactly what will change and changes nothing.

Windows (any one of these; they all run the same installer):

# preview only, nothing is changed
.\install.ps1 -DryRun
# the real install; choose where you will use Claude
.\install.ps1 -Surfaces terminal,desktop

You can also double-click install.cmd or install.exe, or run them with --dry-run first.

macOS / Linux / Git Bash

./install.sh --dry-run
./install.sh                                 # asks you to type INSTALL before touching anything
./install.sh --yes --surfaces terminal,ide   # unattended

Surfaces are where you use Claude: terminal, ide (VS Code and similar) and desktop (the Claude Desktop app). You can add more later.

Safe to try Cortex only removes files it installed. Your official Claude Code, your IDE extensions and your own ~/.claude content are left alone. To remove it later: ./uninstall.sh shows a dry run, ./uninstall.sh --yes removes it.

Check the install

cc version
cc doctor

cc doctor lists problems it can find. A warning that a profile "will re-run onboarding" just means that account has not been signed in yet (next section). To let it fix what it can:

cc doctor --repair

Get started

2 Accounts (profiles)

A profile is one Claude account with its own saved login, so you can switch between work, personal and others without logging out.

  1. See what you have. 
    cc profile list
    The starred row is the active profile. The state column says available, signed out or unknown (no usage recorded yet).
  2. Already use Claude on this computer? Let Cortex find your existing folders without changing them, then adopt them in place. 
    cc profile detect
cc profile adopt work
  3. Make a new profile and sign in. 
    cc profile add work
cc login work
    A browser window opens for the Claude login. Sign in with the account you want for this profile.
  4. Confirm it is signed in. 
    cc profile verify work
  5. Choose the active profile, and start working. 
    cc switch work       # make it the default
cc                   # start a session on the active profile
cc work              # or start one on a specific profile
cc continue          # resume the last conversation

See your quota: cc status (or cc quota) shows how much capacity each account has left. A profile with no usage data yet shows as unknown until you work in it once.

Use the Claude Desktop app on a profile: cc desktop work opens Desktop on that profile's own data. cc desktop list shows the options.

Choose where a profile is used: cc profile surfaces work terminal,ide,desktop, then cc ide apply work --yes to set up your IDE for it.

Handy launch options
CommandWhat it does
cc -s / cc -o / cc -HStart on Sonnet 5 / Opus 5 / Haiku 4.5
cc --fable, --opus-5-5, --sonnet-5-5Start on Fable 5.1 / Opus 5.5 / Sonnet 5.5
cc -e highReasoning effort: low, medium, high, xhigh or max
cc -tTurbo: Haiku with low effort, for cheap quick jobs
cc -ySkip permission prompts. Only use in folders you trust.

Handy for quick checks without leaving your session. They cost no tokens.

Works in a chatExamples

Health/cc doctor · /cc ide · /cc mcp · /cc version
Models/cc model

4 Providers: connect, switch, set a default

A provider is where the model runs. By default you use your Claude subscription. You can add others and choose which one is active.

ProviderWhat it isNeedsDefault model
oauthYour Claude subscription (the normal way)Just cc loginclaude-sonnet-5
anthropicAnthropic API, pay per tokenAn API keyclaude-sonnet-5
openrouterOne key, hundreds of models, many are freeAn OpenRouter keynvidia/nemotron-3-ultra-550b-a55b:free
geminiGoogle Gemini through a local translator on port 8088A Google AI Studio keygemini-2.5-pro

See where you stand

cc provider

The table shows each provider, whether its key is set, its model, and which one is ACTIVE.

Connect a new provider

  1. Get a key from the provider's website (an Anthropic Console key, an OpenRouter key or a Google AI Studio key). Treat it like a password.
  2. Save it. Leave the key off the end of the command and you are asked for it privately, so it does not land in your shell history. 
    cc provider key openrouter
  3. Pick the model for that provider (optional; a default is already set). 
    cc provider model openrouter google/gemma-4-31b-it:free
  4. Make it the active provider (this is also how you switch and how you set the default): 
    cc provider set openrouter

Switch, set the default, go back

GoalCommand
Switch to another providercc provider set anthropic (or use, same thing)
Set the defaultThe active provider is the default. It is saved and stays after you close the terminal.
Change a provider's modelcc provider model <provider> <model-id>
Go back to your subscriptioncc provider reset
A saved provider is used the next time you start cc cc provider set openrouter is enough: the next cc session you start uses it. A session that is already open keeps what it started with, so close it and start a new one. If the provider has no key saved, cc stops and tells you, instead of quietly billing your subscription. To skip the saved provider for one launch, set CORTEX_NO_PROVIDER=1 first. For openrouter and gemini, cc also starts the local translator on port 8088 that these providers go through.
Using a provider outside cc cc provider env <name> prints the settings as export NAME='value' lines, for when you start Claude Code some other way. In PowerShell set each as $env:NAME = 'value'.
Where your key is stored In ~/.claude/providers.json, readable only by your account where the operating system supports it. It is plain text on disk, so do not copy that file around or put it in a repository.

Models & providers

5 Finding and choosing models

cc model          # Claude models plus the OpenRouter catalog with prices
cc model free     # only the models that cost nothing

The list shows every Claude model you can start with (with the flag for each, like cc --opus-5-5) and the OpenRouter models with their context size and price per million tokens. The OpenRouter list is cached and refreshed when it gets old.

Searching the list

Pipe the output through a filter to search by name:

# PowerShell
cc model | Select-String deepseek
# macOS / Linux / Git Bash
cc model | grep -i deepseek

Use a model you found

cc provider set openrouter
cc provider model openrouter google/gemma-4-31b-it:free
cc                            # start a new session; it now uses OpenRouter
Free does not mean private Free OpenRouter models are run by third parties and may keep or train on what you send. For private code use a local model (next section).
Price shows "varies" Router entries such as openrouter/auto pick a model per request, so OpenRouter reports no fixed price and the table shows varies.

6 Local models (no cloud, no account)

Run Claude Code against a model on your own computer. It works offline and nothing leaves your machine.

Be realistic Small local models are good for short, well-scoped tasks and not as capable as Claude. Cortex does not claim any model is proven with Claude Code; the doctor step below measures it on your machine.

Which model?

The built-in suggestion list is aimed at a laptop with about 6 GB of graphics memory. Sizes are what Hugging Face listed on 2026-10-11 and may change.

IDSizeFree RAM neededGood for
qwen3.5-4b2.7 GB~2.5 GBRecommended first model. Fits in 6 GB of video memory, fast helper.
qwen3.5-9b5.7 GB~4.5 GBRecommended. Daily driver for short, well-scoped coding tasks.
mellum2.1-12b-a2.5b7.0 GB~5.5 GBExperimental. Fast, but nobody has reported it through Claude Code.
qwen3-coder-30b-a3b12.9 GB~10.5 GBFallback. Needs the whole machine.
qwen3.6-35b-a3b13.2 GB~11 GBFallback. Strongest that fits at all.
gpt-oss-20b12.1 GB~10 GBFallback. Mature llama.cpp support.

Step by step

All of these are Terminal commands. Downloads are refused inside a chat, even with --yes, so a person has to run them.

  1. Look at your hardware. 
    cc local status
  2. Install the engine (llama.cpp). It shows the size and a checksum and asks before downloading. 
    cc local install --runtime
  3. Search for models (search only, downloads nothing), or skip to the next step to use the suggestion list. 
    cc local search qwen coder
  4. Install a model. Start small. You can use a suggestion ID or any owner/repo from Hugging Face. 
    cc local install qwen3.5-4b
cc local install qwen3.5-4b --dir D:\models   # optional: choose the folder
    It looks up the real file, size and hash at that moment and asks you before it fetches anything.
  5. Choose which one is active, and test it. 
    cc local list
cc local use qwen3.5-4b
cc local doctor --smoke
    --smoke really starts the model and measures speed. Without it, doctor only checks that the pieces exist.
  6. Use it. 
    cc offline
    This starts the model server and Claude Code on top of it. When you are done: cc local stop frees the memory.
Other local commands
CommandWhat it does
cc local serve [id]Start only the model server and gateway
cc local logs [server|gateway]Last log lines, for when something is slow or broken

cc local runtime --path EXEUse a llama-server you already have

Memory & tools

7 Memory palace (project memory)

Claude forgets everything between sessions. The palace keeps lessons, decisions and solved bugs per project and brings the relevant ones back automatically.

  1. Set it up once per project. Open your project folder, then: 
    /cc palace init       # in a terminal, drop the slash:  cc palace init
    No questions are asked. It prints where the palace lives and whether it linked to the project map.
  2. Save something worth remembering. 
    /cc remember decisions "We use SQLite in tests because CI has no database"
  3. Find it later. 
    /cc recall sqlite tests
  4. Check it is healthy. 
    /cc palace status
/cc palace doctor
CommandWhat it does
palace listList memories
palace expandShow one memory in full
palace pin / unpinKeep a memory always on
palace archive / restoreHide a memory reversibly
palace supersede OLD NEWMark one memory as replaced by another
palace forgetDelete permanently (cannot be undone)
palace aboutMemories tied to a file or function
palace verifyCheck files and names in some text against the real code
palace injectTurn automatic memory in prompts on or off for this project
palace groundCheck Claude's answers for invented file or function names (off by default)
palace exportWrite the palace out as Markdown files
Also by chat The memory-palace skill (see the Skills page) tells Claude to look up lessons before non-trivial work and to save them after solving something.

8 The project map and floating button

An interactive map of your project's structure, so you and Claude can see how things connect.

cc graph status    # what exists for this project (also works in chat)

cc graph serve     # serve it and print the address
cc graph button    # the floating button

Running cc palace init links your memories to the map when a map exists.

Memory & tools

9 MCP tools (extra abilities for Claude)

MCP is the standard way to give Claude extra tools. Cortex ships one server so Claude can use your memory and checks directly.

cc mcp add work     # register it for the profile "work"
cc mcp test         # start it and list its tools

A healthy test lists 7 tools: account_status, recall_memory, remember, verify_refs, analyze_code_risks, decompile_binary and evaluate_impact.

Other MCP servers failing? Servers from other plugins (GitHub, cloud, browser and similar) fail on their own for reasons such as a wrong token or a timeout. That does not affect Cortex's own server.

Skills

10 Skills: what they are and how to use them

A skill is a packaged set of instructions Claude loads when a task matches. You do not need to memorise them.

Two ways to use one

  1. Just describe the job. "Review this C++ file for ownership bugs" makes Claude pick cpp-systems by itself.
  2. Name it. Type / followed by the skill name, for example /speckit-specify. You can also write "use the algorithms skill".

Engineering skills

SkillUse it when
memory-palaceBefore non-trivial work on a familiar codebase, and after solving something worth remembering.
algorithmsData structures, LeetCode-style problems, Big-O reasoning.
cpp-systemsWriting, reviewing or debugging modern C++ (RAII, move semantics, const correctness).
systems-architectureDesigning a service or backend: scaling, sharding, caching, failure modes.
hardware-performanceCache, SIMD, branch prediction, CUDA or Triton kernels, roofline analysis.
design-engineeringBuilding or reviewing interface code: layering, typography, micro-interactions.
live-pairingPair-programming mode: it discusses approaches at step boundaries, starts building when you agree, then asks for follow-up changes.
binary-analysisInspecting a compiled program or library with the isolated Ghidra setup. Only for files you own or are allowed to analyse.
scrapling-officialScraping or crawling sites, including JavaScript pages and anti-bot protection. Respect each site's terms.

Spec Kit: plan a feature before you build it

These skills turn an idea into a written spec, a plan, tasks and finally code. Run them in this order in the project folder.

StepSkillWhat it does
1speckit-constitutionWrites your project's ground rules (do once)
2speckit-specifyTurns a plain-language idea into a feature spec
3speckit-clarifyAsks up to 5 targeted questions about gaps and writes the answers into the spec
4speckit-planProduces the design and plan
5speckit-tasksProduces an ordered task list
6speckit-analyzeChecks spec, plan and tasks agree with each other (changes nothing)
7speckit-implementDoes the tasks
8speckit-convergeCompares the code to the plan and adds any unbuilt work as new tasks
–speckit-checklistBuilds a quality checklist for the feature (any time after step 2)
–speckit-taskstoissuesTurns the tasks into GitHub issues
Example In chat: /speckit-specify A page where users can export their data as CSV. Review the result, then continue with /speckit-clarify.

Security skills

The claude-red collection and related skills (web, network, cloud, mobile, exploit development and more) are for authorised testing of systems you own or have written permission to test. Say what you own and which address is yours before asking for anything active. Reading and code review need no setup.

Slash commands that come with Cortex

Type / in a chat to see the full list. A few useful ones: /cc (command index), /provider, /model, /capacity, /palace, /remember, /recall, /effort, /turbo, /switch, /continue, /clean.

/cc versus /provider /cc … commands run on your machine and cost nothing. Slash commands like /provider are instructions to Claude, so they use a little of your usage.

12 Troubleshooting

Typing cc prints compiler errors

You launched the C compiler instead. Use PowerShell or Command Prompt, or run cc.cmd explicitly.

"A hook blocked your prompt" after /cc …

Expected. Read the first line of the result: done means it worked, FAILED (exit N) means read the text below it.

The chat says a command "cannot run inside a prompt"

It might start a login, a session, a server or a download. Run the terminal command it prints.

cc profile list says "signed out"

Run cc login <name> in a terminal, then cc profile verify <name>.

I set a provider but Claude still uses my subscription

Close the open session and start a new cc; a running session keeps the provider it started with. Check cc provider status shows your choice as ACTIVE, and that CORTEX_NO_PROVIDER is not set.

cc or cc provider env says the provider has no API key

Save one with cc provider key <name>, or go back to your subscription with cc provider set oauth.

cc offline says no local model is installed

Do steps 2 and 4 on the Local models page.

cc local doctor shows FAIL: runtime missing

Run cc local install --runtime in a terminal.

Some MCP servers show "failed to connect" at startup

Those are other plugins (token, network or timeout problems). Check Cortex's own with cc mcp test.

Memory does not seem to come back

Run cc palace status and cc palace doctor in the project folder. Check cc palace inject has not been turned off. Memories only come back when the words of your prompt match something saved.

Something looks wrong and I want it checked automatically

cc doctor --repair fixes what it safely can.
